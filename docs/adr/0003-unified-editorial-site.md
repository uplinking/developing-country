# Use Astro and EmDash as one editorial application

The landing page, country desks, Research Articles, admin UI, previews, media, and editorial MCP are one Astro 7 application with EmDash on a single Cloudflare Worker. Public pages are server-rendered from EmDash D1 content and custom Portable Text blocks; media belongs in the CMS R2 bucket. We do not operate a separate blog application or headless-CMS vendor.

Agents connect to the EmDash MCP as a **Contributor** and submit a complete draft in one `content_create` call. The Contributor role is the enforcement boundary: it can create content but lacks both `content:edit_own` and `content:publish_own`, so a token with `content:write` can neither revise nor publish after submission. A human Editor or Admin verifies evidence, handles requested revisions, and publishes in the admin UI. Instruction files reinforce this workflow but are not the security boundary. EmDash has no built-in edit-without-publish role, so upgrading an agent identity to Author is prohibited.

Interactive figures use the native `dcLiveView` block. It stores one allowlisted canonical `https://explore.developing-country.org/views/view_…` URL and renders it in a sandboxed iframe. It never copies rows, chart configuration, geometry, screenshots, or arbitrary HTML into the CMS. Because the platform URL is the artifact returned to the MCP client, the MCP App, standalone explorer, and published article remain the same live result.

Custom blocks are a trusted local package, not dynamically loaded marketplace code. This avoids Cloudflare Workers for Platforms / Dynamic Worker Loader and its paid-plan floor. EmDash runs its own CMS migrations; the site D1 migration directory is explicitly isolated from the platform Worker migrations.

The Cloudflare adapter generates the `SESSION` KV binding used by Astro sessions. Current Wrangler resource auto-provisioning accepts this ID-less generated binding; `wrangler deploy --dry-run` validates it and reports the binding without a manually created namespace. The site schedules both EmDash lanes: the one-minute general/publishing tick and the two-minute media-usage maintenance tick.

Anonymous public documents use native Workers Cache with short freshness and stale-while-revalidate windows. Cached markup is host- and session-independent: canonical URLs always use `developing-country.org`, the Worker is custom-domain only, and the public shell has no login-dependent fragments. A Worker wrapper adds `private, no-store` to every non-public response and every `_preview` request, because Workers Cache may otherwise apply heuristic freshness even where Astro has no route rule. Admin, auth, API, media, preview, and editorial MCP responses are therefore outside the shared cache boundary.
