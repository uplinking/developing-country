# Serve PMTiles directly from an R2 custom domain

Production MapLibre and PMTiles clients read immutable archives from `https://tiles.developing-country.org`, a custom domain attached directly to the `developing-country-tiles` R2 bucket. Browser range reads therefore consume neither a Worker request nor Worker CPU. The explorer's `/tiles/*` proxy and `/xyz/*` adapter remain compatibility and diagnostic seams, not the production browser path; the Worker still binds `TILES` for the walk graph and those fallbacks.

The bucket CORS contract is tracked in `scripts/r2-tiles-cors.json`: public `GET`/`HEAD`, range validators, and the response headers PMTiles needs. A wildcard origin is appropriate because the archives are public evidence and MCP Apps run inside host-dependent sandbox origins. The zone must also carry one Cache Rule matching only `http.host eq "tiles.developing-country.org"` with cache eligibility enabled, Edge TTL of one day, and Browser TTL of one hour; `.pmtiles` is not one of Cloudflare's default cached extensions. Current operational keys can be refreshed in place, so these bounded TTLs prevent long-lived stale archives. Future immutable PMTiles Dataset Versions should move to content-addressed keys before extending TTLs.
